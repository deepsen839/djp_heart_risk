# DJP Heart-Risk ML Proof of Concept — Technical Summary

## Executive summary
A research/demo-only supervised-learning pipeline is provided for the HackBase DJP technical assignment. It audits a public UCI Heart Disease benchmark, compares a dummy baseline and conventional classifiers, evaluates a held-out test partition, packages preprocessing with the selected estimator, and exposes local inference through FastAPI. It is not a diagnosis or clinical risk tool.

## Dataset and quality
Source: UCI Heart Disease dataset (ID 45), Cleveland subset. Runtime retrieval date, row/column counts, duplicates, missingness, range checks, class balance and field dictionary are generated by `djp-audit` in `reports/`. The source target is binarised from 0 versus 1–4. No stable patient ID is supplied. The dataset is small and historical and is not representative of DJP, a clinic or an Indian deployment cohort. Review current UCI terms before redistribution.

## Method
Stratified 60/20/20 train/validation/test. Five-fold stratified CV is limited to training data. Candidate selection uses validation ROC-AUC (CV ROC-AUC tie-break); test data are untouched until final evaluation. Imputation, scaling and one-hot encoding are in a scikit-learn pipeline. The selected complete pipeline is refit on train+validation and persisted.

## Models and results
Candidates: DummyClassifier, Logistic Regression, Random Forest, XGBoost (or ExtraTrees if XGBoost is unavailable). Actual comparison is generated in `reports/model_comparison.csv`; actual held-out metrics are generated in `reports/evaluation.json`. Do not insert or claim results until the pipeline has run. Report accuracy, precision, recall, F1, confusion matrix, ROC-AUC where meaningful and Brier score. Calibration plot is descriptive and may be unstable because of the small test sample.

## Architecture and API
See README architecture diagram. FastAPI `/predict` returns a model-estimated score, optional provisional LOW/MEDIUM/HIGH demonstration band, model/pipeline versions and fixed disclaimer. The provisional 0.25/0.75 cut points are not clinically validated.

## Safety, privacy and limitations
No identifiable patient data. The ML model never determines emergency status. A separate mock clinician-rules port passes through a supplied fixture and is tested to preserve `emergency_flag=True` independently of model score. Actual emergency criteria and workflows require qualified clinician approval. Permutation importance is associational, not causal. A descriptive sex/age-band error review is generated where subgroup sample sizes permit, with small-cell warnings. Small sample, historical data, target simplification, missingness, dataset shift and subgroup sample limits constrain conclusions.

## Recommendation
Treat this as a reproducible technical demonstration only. Before any clinical research extension, obtain appropriate governance and clinician ownership, define intended use, obtain a fit-for-purpose authorised cohort, validate externally and prospectively, assess subgroup performance and calibration, and approve any thresholds/workflows through the clinical owner.


## Local application and container delivery

The project includes a Streamlit dashboard and Docker packaging. Streamlit calls FastAPI over HTTP; FastAPI remains the inference boundary. Docker Compose defines separate API and dashboard services plus an opt-in training profile. The dashboard communicates the research-only disclaimer and demonstrates emergency-rule independence through a mock-only input.
